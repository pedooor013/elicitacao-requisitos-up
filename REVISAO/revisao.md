Fundamentos da Engenharia de Requisitos
    - O que é um requisito:
        "Requisito é uma especificação de uma necessidade que o sistema deve atender";
        - Existe 3 níveis de requisitos:
            - 1º: Requisito de negócio;
            - 2º: Requisito de usuário;
            - 3º: Requisito funcional;
            - OBS: Requisito não funcional também é uma propriedade, atendendo restrições e qualidades, exemplo: um pedido deve ser feito com três cliques;
    - O que é um stakeholder?
        - É quem tem interesse no sistema, exemplo: Investidor (Quem quer que o produto de lucro), Programador (Quem da manutenção no sistema), Usuário (Quem usa o sistema), etc.

Engenharia de Requisitos em Projetos Ageis
    - Vocabulario Agil:
        - Product Owner: O dono do projeto que decide a prioridade;
        - Product Backlog: Lista organizada e priorizada de tudo que o produto deve atender;
        - Refinamento: Quebra um item vago em histórias mais precisas antes da iteração;
        - MoSCoW: Must, Should, Could, Won't. Uma forma de priorizar o backlog;
            - Must: Muito importante;
            - Should: Importante, mas deixa pra se der tempo;
            - Won't: Não é importante, deixa para depois ou nem fazemos;
    - Historia do Usuário:
        - Exemplo de uma história de usuário:
            - Como <Tipo de usuário>, quero <Um objetivo>, para <uma razão>;
        - Para sabe se uma história de usuário é boa ela deve ser:
            - I - Independente;
            - N - Negociável;
            - V - Valiosa;
            - E - Estimável;
            - S - Pequena;
            - T - Testável;
    - Critério de Aceitação:
        - Exemplo de um criterio de aceitação:
            - Dado que <situação>, quando <ação>, então <resultado esperado>;

Tipo de Requisito e Critérios de Qualidade:
    - ISO/IEC 25010, oito características de qualidade:
        - Adequação funcional;
        - Eficiencia e desempenho;
        - Compatibilidade;
        - Usabilidade;
        - Confiabilidade;
        - Segurança;
        - Manutenibilidade;
        - Postabilidade;

Levantamento de Requisitos e Fontes de Informação:
    - Fontes Não Humanas:
        - Documentação;
        - Sistema Legado;
        - Concorrência;
        - Normas;

Tecnicas de Levantamento de Requisitos:
    - Perguntar:
        - Entrevista;
        - Questionário;
        - Workshop;
    - Observar:
        - Observação;
        - Análise documental;
        - Análise de sistema legado;
    - Explorar e Construir:
        - Prototipação;
        - Brainstorming;
        - Workshop;

Design Thinking:
    - Quando usar:
        - Nem o problema real nem solução estão claros;
    - Quando não usar:
        - Quando o cliente já sabe o que quer, entrar no ciclo atrasaria só a desição;
    - Etapas:
        - 1ª Empatia;
        - 2ª Definição;
        - 3ª Ideação;
        - 4ª Prototipação;
        - 5ª Teste;
